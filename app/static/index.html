Allowed repository mirrors

Choose which repositories your APT clients can reach through this proxy.

Enter one hostname per line, such as download.docker.com. A leading dot, such as .ubuntu.com, also allows subdomains. Use hostnames only; omit https:// and repository paths. HTTPS traffic is allowed but its contents cannot be cached.

Saving replaces the allowlist and requests a Squid reload. Removing a host can block future package downloads from it. Changes persist across container restarts.

Connect an APT client

Copy and run these commands on each Debian or Ubuntu client.

Use the Docker host’s address reachable from the client and the published proxy port (default 8000), rather than the dashboard port. For remote clients, set PROXY_BIND to the server’s LAN IP in .env and run docker compose up -d on the server first. Localhost works only when the client runs on the Docker host.

1. Configure the client

This writes the dedicated APT proxy file, replacing it if it already exists, refreshes Docker’s signing key if its Ubuntu repository is configured, and refreshes package indexes. The Docker step requires curl and a Docker source entry pointing to /etc/apt/keyrings/docker.asc.
